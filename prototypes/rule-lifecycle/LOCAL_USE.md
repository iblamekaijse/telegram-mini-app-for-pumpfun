# Регулярное локальное использование

Выпуск **v0.1.0-paper.1**, актуальный код **main**, SQLite **v7**. Node.js **24.19.0**, команды из `prototypes/rule-lifecycle` внутри существующего WSL checkout. Установка npm-пакетов не нужна. Приложение работает только пока включены компьютер, WSL и процесс `npm start`. При выключенном компьютере нет рыночного опроса, обработки виртуальных правил и уведомлений.

Единственный последовательный путь обновления → согласованной копии → настройки → запуска приведён в [HANDOFF.md#update](../../HANDOFF.md#update). Не переустанавливайте проект и не удаляйте `.env`/`.local-web`. Здесь — справка по тем же командам; повторять пользовательский сценарий после каждого шага не требуется.

## Настройка и запуск

`npm run setup` показывает фактические пути `.env` и SQLite. По умолчанию конфигурация — `.env` текущего каталога приложения, данные — `.local-web/state.sqlite`. `DEMO_ENV_FILE` выбирает другой файл. Существующие `DEMO_DATA_DIR`/`DEMO_PORT` учитываются; относительный путь данных разрешается от текущего рабочего каталога. Унаследованные переменные оболочки имеют приоритет над файлом, как и раньше. При отличии значений проверьте их имена/источник, не выводя содержимое `.env`.

Если токена нет, setup запросит его **скрытым вводом в терминале**. Создайте обычного бота через официальный @BotFather и вставьте токен только туда. Существующий токен используется без повторного ввода; для перевыпущенного токена — `npm run setup -- --replace-token`. Токен проверяется через `getMe`; это подтверждает токен/ID и доступность API, но не доставку сообщений и не весь цикл. Ошибки и журналы не содержат токен/секретный URL. Команда сохраняет остальные настройки, атомарно записывает файл с правами **600**; новые каталоги конфигурации имеют права 700. Токен, базы и копии не добавляйте в Git.

Настройка уже существующей базы требует остановленного приложения; занятая/повреждённая база не пересоздаётся. После успешного setup выполните `npm run doctor`, затем `npm start`. Запуск не задаёт интерактивных вопросов. Для первой привязки получите одноразовый код в локальной панели и отправьте его в личный чат своего бота; существующая привязка того же бота сохраняется. Не запускайте два экземпляра с одним токеном или одной базой. Завершение — **Ctrl+C** в окне сервера, дождитесь возврата приглашения оболочки.

Если TELEGRAM_BOT_TOKEN унаследован из оболочки, он перекрывает `.env`. После замены локального токена setup предупреждает, когда нужно выполнить `unset TELEGRAM_BOT_TOKEN` перед запуском. При пустом токене Telegram отключён, панель и виртуальный рыночный цикл работают. `npm start` автоматически читает выбранный `.env`; в командную строку токен не передаётся.

## Идентичность бота

SQLite v7 сохраняет **ID бота**, полученный через getMe. При каждом старте getMe и getWebhookInfo выполняются **до getUpdates, отправки очереди, Telegram-команд и диалоговых source-jobs**. ID из конфигурации и базы должны соответствовать ответу API. До проверки нельзя создать новый код привязки. Неизвестный ID или несовпадение останавливает только Telegram-интерфейс; история/позиции сохраняются.

- **Перевыпуск токена того же бота:** getMe возвращает прежний ID; сохраняются offset, владелец, кнопки, очередь, диалог, правила и позиции. Используйте `setup -- --replace-token`.
- **Переход с прежней SQLite v6:** ID раньше не записывался. Setup честно сообщает, что старую личность нельзя установить автоматически. Если это ваш прежний бот, подтвердите показанный ID в терминале: это явное принятие существующей привязки, без сброса. Неинтерактивный эквивалент — `npm run setup -- --adopt-bot ID_ПРЕЖНЕГО_БОТА` с точным ID, проверяемым getMe.
- **Другой бот:** отдельное локальное действие `npm run setup -- --replace-token --switch-bot ID_НОВОГО_БОТА` (либо явное подтверждение «СМЕНИТЬ ID» в setup). ID должен точно совпадать с getMe. Сбрасываются только Telegram offset/pending, привязка, код, кнопки, диалог и очередь, увеличивается поколение полномочий. Торговые правила, позиции и история остаются. После запуска привяжите владельца новым кодом. Старые сообщения нового бота не получают прежние полномочия.

ID — не токен. Токен ни при каком варианте не передавайте параметром команды. Отключение привязки из панели остаётся отдельным действием и не меняет сам бот.

## Диагностика

`npm run doctor` выводит короткие строки: **исправно**, **не настроено**, **не проверено**, **ошибка** и следующее действие. Проверяются Node, пути/права конфигурации, поддерживаемая версия/целостность базы, локальная панель, Telegram getMe, совпадение ID, webhook и известное состояние рынка. `getMe` не означает, что сообщения доставляются. Ненастроенный/непроверенный компонент не объявляется готовым. При ошибке код завершения 1.

Для работающего приложения doctor использует `/api/diagnostics` того же локального сервера и сверяет путь базы. Этот endpoint не обновляет срок правил, не обрабатывает команды и не мигрирует базу. При остановленном сервере база открывается **read-only**, проверяется checksum/целостность/версия без миграции. Doctor не создаёт данные, не открывает второй обработчик, не вызывает getUpdates/sendMessage/deleteWebhook, не запускает лишний рыночный опрос. Привязка и содержимое .env не выводятся. Когда сервер остановлен, «панель/рынок не проверено» ожидаемо. Если приложение запущено с нестандартным путём/портом, используйте тот же DEMO_ENV_FILE и те же настройки; при занятой базе без доступной панели проверка явно сообщает ошибку.

| Результат | Действие |
| --- | --- |
| 401/403 | Проверьте/перевыпустите токен в BotFather; `npm run setup -- --replace-token`, затем doctor и запуск. |
| 409 | Остановите второй getUpdates-процесс с тем же ботом. Проверьте webhook; исходная установка не должна продолжать polling после запуска восстановленной. |
| Webhook активен | Штатно отключите webhook в системе, которая его установила, либо явным вызовом официального deleteWebhook из доверенного клиента с локальным токеном. Doctor/setup его автоматически не снимают; токен в URL/чат/журнал не копируйте. |
| 429 | Подождите указанное Telegram Retry-After. Runtime использует backoff; повтор сообщений ограничен прежними пятью попытками. Не запускайте несколько экземпляров. |
| BOT_IDENTITY_REQUIRED | Остановите сервер и подтвердите прежний ID локально в setup; v6 не знала его автоматически. |
| BOT_IDENTITY_MISMATCH / BOT_CONFIG_MISMATCH | Проверьте, какой бот нужен. Для нового — явный `--switch-bot ID`, для прежнего — правильный токен того же ID. |
| STORAGE_BUSY | Ctrl+C у владельца базы, дождитесь завершения; проверьте фактический путь. Не удаляйте файл/каталог/историю ради запуска. |
| Неподдерживаемая/повреждённая база | Сохраните файл и используйте совместимую копию/версию программы. Doctor/restore не заменяют её пустой историей. |
| Нет рыночных данных | Дождитесь восстановления источника и нового пригодного снимка. Не используйте сохранённую оценку как текущую; пул/unknown/однократность не обходятся. |

После Ctrl+C и нового старта читается прежняя история. Pending Telegram update восстанавливается после проверки ID; очередь и offset сохраняются. Рыночная оценка становится актуальной только после нового пригодного снимка. Submitted без сохранённого результата остаётся unknown с запретом повтора. Перезапуск не снимает ограничения источника и не создаёт вторую позицию.

## Копия и восстановление

Остановите приложение. `npm run backup` создаёт отдельный каталог под `~/pumpfun-backups/`; можно указать `npm run backup -- --to /абсолютный/новый/каталог`. Путь выводится после успешного завершения. Команда определяет настоящую базу из той же конфигурации, получает **эксклюзивную блокировку SQLite**, проверяет DELETE journal mode, checksum, целостность и версию, копирует под блокировкой и проверяет результат. Работающий экземпляр приводит к отказу **до создания копии**, а не к копированию открытой базы. Иной режим журнала не копируется небезопасным способом. Отдельный manifest содержит версии, имена файлов и хеши, не секреты. Конфигурация проверяется на изменение во время копирования. Файл токена локальный: каталог 700, файлы 600. Копию не публикуйте. Значения, существующие только в переменных оболочки, автоматически в копию не экспортируются.

Нормальный путь восстановления:

```bash
npm run restore -- /абсолютный/путь/копии --to /абсолютный/новый/каталог
```

В новом каталоге будут `data/state.sqlite` и `.env`. DEMO_DATA_DIR в копии конфигурации перенаправляется **в новый каталог**, чтобы не открыть исходную базу. Команда выводит готовый запуск с DEMO_ENV_FILE и DEMO_DATA_DIR; выполните его **из того же checkout приложения** после остановки старой копии. Перед запуском можно направить doctor на тот же файл. Восстановление не запускает приложение и не отправляет сообщения. Это состояние на дату копии, включая доступ владельца/очередь/offset. Текущий токен/API проверяются заново; токен, перевыпущенный после копии, при необходимости вводится скрыто через setup.

Если целевой каталог уже существует, по умолчанию отказ. Для перезаписи прежнего каталога восстановления требуется `--confirm-path /тот/же/точный/каталог`; его старая версия сохраняется рядом как `.before-restore-*`. Сначала проверяется маркер .local-restore.json прежнего восстановления; произвольный рабочий каталог таким способом не заменяется.

Для явно выбранной **действующей базы** есть отдельный режим:

```bash
npm run restore -- /путь/копии --overwrite-db /полный/путь/state.sqlite --confirm-path /полный/путь/state.sqlite
```

Оба пути должны точно соответствовать текущей базе из doctor. Требуется остановленное приложение и проверка блокировки; перед перезаписью создаётся отдельная согласованная копия действующей базы/конфигурации. Восстановление использует прежний SnapshotStore, сохраняя inode/блокировку, а не удаляет рабочую базу. Укажите тот же DEMO_ENV_FILE, если он нестандартный. Несовместимая версия, неверный checksum, повреждённая или пустая копия прекращают операцию без создания пустой истории. Если файловая ошибка прервала запись конфигурации/базы, doctor покажет несоответствие; до запуска используйте сохранённую предшествующую копию. Настройка или восстановление, которые не завершились, не объявляются успешными.
