# Локальная веб-панель — DEMO

Один сквозной сценарий через браузер: создание и включение правила → тестовая цена → решение ядра → результат имитатора → восстановление после перезапуска. Панель работает с существующим `RuleEngine`, его `SyntheticSource`/`SourceConsumer` и тем же SQLite-хранилищем. Это практический интерфейс прототипа, не утверждение окончательного формата продукта.

## Запуск

Node.js >= 22.13 с `node:sqlite`, проверено на 24.19.0. Только стандартные модули Node.js; npm install не нужен.

Из корня репозитория:

```sh
cd prototypes/rule-lifecycle
npm start
```

Адрес: **http://127.0.0.1:4173**. Остановка — Ctrl+C; повторный запуск той же командой откроет сохранённую историю. Сервер слушает только `127.0.0.1`; он не публикуется в интернет и не предоставляет доступ с другого устройства. Интерфейс адаптирован к узкому экрану браузера.

При необходимости можно задать другой порт или отдельный новый каталог данных:

```sh
DEMO_PORT=4174 DEMO_DATA_DIR=/tmp/my-rule-panel npm start
```

Родитель каталога должен существовать. Настройка каталога — локальная конфигурация, для обычного сценария менять её не требуется.

## Как пройти сценарий

1. Оставьте тестовый актив A, цену условия **1.00**, сумму **10.00**, срок **10 минут**, нажмите **«Создать правило»**. Можно указать свои тестовые значения; ошибки показываются возле полей.
2. Нажмите **«Включить правило»**. Только создание не включает его.
3. В отдельном **DEMO-пульте** выберите «Успех», передайте **1.20**: событие сохранится, условие не выполнится. Затем передайте **0.90**: ядро подготовит операцию, имитатор вернёт успех. Карточка, последняя цена и журнал обновятся из серверного состояния.
4. Перезагрузите страницу. Остановите сервер Ctrl+C и запустите снова. Результат и история сохранятся, второй покупки не возникнет.

Все значения выше вымышленные, не реальные торговые пороги. Цена — число `DEMO:QUOTE-A` за одну условную целую единицу актива; 2 десятичных знака, внутри ядра — целые минимальные единицы. Сумма тоже выражена в этой вымышленной валюте. Имитатор использует синтетическую квитанцию, а не рыночный расчёт обмена.

Чтобы проверить другой исход, после завершения нажмите **«Новое DEMO-правило»**, явно создайте и включите отдельное правило, затем выберите «Неудача» или «Неизвестно» в пульте. Старые правила и их операции не удаляются; они видны в журнале и разделе предыдущих правил. Текущий незавершённый сценарий сначала нужно окончательно отозвать. Это отдельное новое правило, а не повтор заблокированной попытки.

`unknown` отображается как **«Исход операции неизвестен»**: новое включение и повторная покупка этим правилом запрещены. Можно посмотреть журнал и окончательно отозвать правило; отзыв не меняет неизвестный результат на отмену. Выбор другого исхода в пульте никогда не исправляет уже отправленную операцию.

В разделе пульта **«Проверить остановку потока»** можно вручную создать DEMO-случай проверки истории. Карточка объясняет `decision_required`; доступны **«Проверить историю»** и окончательный отзыв. Проверка использует сохранённый полный синтетический журнал, оставляет правило на паузе и не снимает `unknown`. Кнопка принятия пропуска отключена. Это тест остановки средствами уже существующего контракта, не новый контракт восстановления и не утрата реальных рыночных данных.

## Что сохраняется и где проходит граница

Основной файл — `prototypes/rule-lifecycle/.local-web/state.sqlite`, каталог исключён из Git. Он создаётся только при первом создании каталога приложения. Если каталог уже существует, а база отсутствует или повреждена, сервер **отказывается запускаться**, не создавая пустую историю. Ошибки хранения не переключают приложение на данные в памяти. Прежняя эксклюзивная блокировка одного экземпляра сохранена.

Через публичные методы ядра читаются правила, операции, решения владельца и события. Для браузерной панели добавлены только read-only `listRules` и `getEventLog`; условия срабатывания, состояния, срок, идемпотентность и блокировки остаются в ядре. Сервер проверяет форму и переводит десятичный ввод в целые единицы; браузер не принимает торговых решений.

Синтетический журнал строится из надёжно сохранённых записей источника. Выбранный исход имитатора сохраняется **в конкретном ценовом событии**. Исполнитель получает его из операции, поэтому изменение радиокнопки и параллельные запросы не подменяют исход другой операции. Передача сохраняет прежние границы `prepared`/`submitted`/результат. После возможной передачи без сохранённого результата восстановится `unknown`, без автоматического повторения. Сохранённое ещё не переданное намерение обслуживается существующим consumer только после проверки истории/срока/свежести.

Изменяющие HTTP-запросы выполняются последовательно и имеют ключи идемпотентности. При обрыве связи интерфейс сохраняет ключ для явного повтора того же запроса; фонового повторения команд нет. Состояние читается каждые 2 секунды, при недоступном сервере кнопки блокируются. Журнал интерфейса показывает последние 40 строк; полная история остаётся в SQLite. Обновление страницы не означает отправку новой цены.

Фиксированные ограничения DEMO: комиссия до 0.01 `DEMO:QUOTE-A`, общий расход до суммы плюс эта комиссия, минимальное получение 1 условной единицы актива, синтетическое проскальзывание 50 б.п., максимальный возраст события 30 секунд. Срок формы — 1…1440 минут. Эти параметры видны в карточке; они нужны для удобного локального теста, не утверждают стратегию или onchain-политику и не доказывают выгодную цену.

## Проверки

```sh
npm test
```

Фактически **112 passed, 0 failed, 0 skipped**: прежние 106 проверок и 6 новых интеграционных проверок серверного слоя. Проверены реальный HTTP, валидация, совпадение размерностей, повторы/конфликты ключей, конкурирующие запросы, успех/неудача/unknown, решения по потоку, сохранение архива и SIGKILL сервера с восстановлением другим процессом. Проверены истечение срока через ядро и отказ запуска с отсутствующей/повреждённой историей. Вывод: [results/web-tests.tap](../results/web-tests.tap).

В доступной среде интерфейс проверен **в Chromium через Python Playwright**, без добавления зависимости в приложение:

```sh
python3 web/browser-check.py
```

Эта дополнительная команда требует уже установленный Python Playwright и Chromium. Она проходит сценарии исключительно через интерфейс, включая перезапуск сервера, unknown/проверку потока/отзыв и неудачу, проверяет отсутствие ошибок JavaScript и горизонтального переполнения на экранах 1440×1050 и 390×844. Сохранены [отчёт](../results/web-browser.json), [снимок компьютера](../results/web-desktop.png) и [телефона](../results/web-mobile.png). Снимки также просмотрены визуально.

## Ограничения

Это локальный доверенный DEMO-доступ, **не настоящая авторизация**. Контекст владельца создаёт серверный bootstrap, область ограничена выбранным правилом; ownerId/контекст из браузерного JSON не принимается как подтверждение прав. Старые API ядра также остаются локальными доверенными входами. Есть базовые проверки Host/Origin и формат JSON, но нет аккаунтов, сессий или промышленной модели доступа. Публичное размещение не входит в этап.

Нет кошельков, реального поставщика, торговых транзакций и подтверждённого onchain-исполнения. `LIVE_TRADING_ALLOWED=false`. Панель не устраняет нерешённые зависимости продукта: авторизацию, подпись/полномочия, сверку неизвестного исхода, финальность реального источника и эксплуатационные гарантии. Сохраняются ограничения одного локального файла, доверенных часов и отсутствие обещания «ровно одного исполнения» внешней операции. Материалы Swig не затронуты; исследование подписи и прежние эксперименты безопасности не возобновлялись.
