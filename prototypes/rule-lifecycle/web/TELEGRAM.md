# Обычный Telegram-бот для виртуального цикла

Ветка `codex/virtual-position-lifecycle`, существующий PR №3. Node.js **24.19.0**, стандартные модули, без npm install. Это Bot API с long polling, без webhook, Mini App, публичного сервера и реальных сделок. Локальная панель остаётся на компьютере; телефон использует обычный личный чат бота. Компьютер с сервером должен быть включён и иметь интернет. При остановленном WSL рыночного опроса и уведомлений нет.

## Обновление

Единственная актуальная процедура обновления с резервной копией — [HANDOFF.md](../../../HANDOFF.md#update). Не удаляйте `.local-web` и не запускайте два экземпляра бота с одним токеном. Сначала остановите сервер. SQLite v1…v4 автоматически мигрирует в v5 без удаления правил, позиций, операций, команд и событий. Откат старого кода на v5 не поддерживается; резервная копия должна быть сделана **до** миграции.

## Локальное подключение токена

Создайте обычного бота через официальный **@BotFather** (`/newbot`). Не отправляйте полученный токен в чат с помощником, не вводите его в браузерную панель и не публикуйте его. В Ubuntu/WSL:

```bash
cd ~/telegram-mini-app-for-pumpfun/prototypes/rule-lifecycle
# Не перезаписывать уже существующий .env:
(umask 077; test -e .env || cp .env.example .env)
chmod 600 .env
nano .env
```

В редакторе локально заполните `TELEGRAM_BOT_TOKEN=` значением BotFather, сохраните и закройте файл. Затем `npm start` из этого же каталога. Скрипт читает `.env` автоматически; унаследованные переменные окружения имеют приоритет. Токен не сохраняется в SQLite, HTTP-ответах, отчётах и журналах приложения. `.env` исключён из Git. Не запускайте приложение с отладочным трассированием HTTP/proxy, которое может записать секретный URL Bot API. При утечке отзовите токен через BotFather.

Откройте локальную панель на том же Windows-компьютере. Внизу находится **Telegram · виртуальный режим**. Нажмите **Получить код привязки**, затем в **личном чате именно своего бота** отправьте показанную команду `/start <код>`. Код одноразовый, действует 5 минут, в базе хранится только SHA-256. Новый код заменяет предыдущий. Не передавайте код другим. Случайный `/start` без кода не даёт доступа. Подтверждённая привязка включает и Telegram user ID, и chat ID; группы, другие пользователи и другие чаты не могут читать состояние или выполнять команды.

Кнопка **Отключить привязку** в локальной панели отзывает доступ, отменяет ещё не отправленную очередь и делает старые кнопки недействительными даже после новой привязки. Уже начатую сетевую отправку отозвать невозможно; она может завершиться после отключения. Для нового владельца требуется новый код; старая история уведомлений не рассылается.

Без токена Telegram выключен; панель, SQLite и рыночные позиции продолжают работать. В панели видны подключение, привязка, очередь и число окончательно недоставленных сообщений. `401/403` — проверьте токен/права, `409` — остановите другой экземпляр getUpdates с тем же токеном, `429` — сервис сам ждёт Retry-After. При старом webhook polling не работает: удалите webhook штатным способом Bot API до запуска; приложение само не меняет чужую конфигурацию бота. При сетевой ошибке опрос бота возобновляется с задержкой; рыночный цикл не ждёт Telegram.

## Команды, уведомления и ограничения

- `/help`, `/start` у привязанного владельца — краткая инструкция, `/status` — актуальное правило, последняя позиция и её расчётные значения.
- Кнопки приостанавливают/включают только конкретное ещё ожидающее входное правило. Кнопка прежнего правила не влияет на новое. Использованные кнопки изменения одноразовые; для следующего действия запрашивайте `/status`.
- Запрос закрытия относится к конкретной открытой позиции: сейчас сохраняется только намерение. Расчёт производится по **следующему новому пригодному снимку**, не по цене из сообщения и не по старому кэшу. `unknown` независимо запрещает повтор соответствующей попытки.
- Уведомления: виртуальный вход, сохранённый ручной запрос, выход TP/SL/по запросу, unknown, потеря и восстановление пригодных рыночных данных. Сообщения содержат источник, актив, основание и расчётные величины; каждый снимок и каждый повтор ошибки не рассылаются. Это локальные наблюдения DEX Screener/PumpSwap, не подтверждённое время/полнота блокчейн-потока.

Привязка, поколение полномочий, кнопки, pending update, offset, распознанные события и outbox сохраняются в существующем SQLite-снимке. Перед командой сохраняется update; бизнес-операция использует стабильный ключ идемпотентности. Offset getUpdates продвигается только после сохранения обработки и ответа в очередь. Если процесс прервётся между бизнес-командой и записью offset, update восстанавливается без повторного торгового действия. События позиций/unknown сопоставляются с сохранённой историей и восстанавливают уведомления после аварии; смена доступности рынка сохраняется вместе с записью уведомления. При подключении фиксируется начальная граница истории.

Перед отправкой сохраняется номер попытки; максимум **5 попыток** с backoff, ошибки `400/401/403` окончательны для сообщения, `429` учитывает Retry-After. Очередь переживает перезапуск. Доставка **не ровно один раз**: если Telegram принял сообщение, но ответ потерялся, после рестарта возможен повтор уведомления. Уведомление никогда не исполняет торговую команду. Окончательно недоставленные сообщения не пересылаются бесконечно; актуальное сохранённое состояние доступно в панели и через `/status`. История и очередь сейчас не очищаются автоматически; это локальный прототип одного владельца, не массовый сервис.

Сетевые getUpdates/sendMessage/answerCallbackQuery выполняются вне общей очереди команд. Команды бота, панели и обработка рыночных снимков используют прежнюю сериализацию и бизнес-логику. Telegram не даёт доступ к HTTP-панели: она остаётся доверенным локальным интерфейсом без аккаунтов. Кошельки, подписи, реальные сделки и публикация приложения не добавлены.

## Одна итоговая приёмка

После обновления и привязки создайте и включите в панели **виртуальную позицию** на выбранном mint. Дождитесь нового снимка, удовлетворяющего вашему условию, и уведомления о входе. В телефоне вызовите `/status`, нажмите **Запросить закрытие позиции**, дождитесь следующего пригодного снимка и уведомления о сохранённом результате. Перезапустите сервер, снова вызовите `/status`: история и результат те же, новой операции нет. Прототип не гарантирует наступление выбранного условия или доступность рынка. Эта единственная приёмка проверяет настоящий Telegram и WSL пользователя; тестовый транспорт их не заменяет.

```bash
npm test
# При установленных Python Playwright и Chromium:
python3 web/telegram-browser-check.py
```

Новый браузерный сценарий использует настоящие HTTP/SQLite и тестовые Telegram/рыночный транспорты с явными ценами 100 → 107. Он проверяет UI-привязку, чужого пользователя, вход/уведомление/status/кнопку, выход +70 USD/+7%, SIGKILL/новый процесс и отключение привязки; снимки desktop/mobile и отчёт — `results/telegram-*`. Настоящий Telegram без пользовательского токена не проверялся.
