# Обычный Telegram-бот для виртуального цикла

Ветка `codex/virtual-position-lifecycle`, существующий PR №3. Node.js **24.19.0**, стандартные модули, без npm install. Это Bot API с long polling, без webhook, Mini App, публичного сервера и реальных сделок. Локальная панель остаётся на компьютере; телефон использует обычный личный чат бота. Компьютер с сервером должен быть включён и иметь интернет. При остановленном WSL рыночного опроса и уведомлений нет.

## Обновление

Единственная актуальная процедура обновления с резервной копией — [HANDOFF.md](../../../HANDOFF.md#update). Не удаляйте `.local-web` и не запускайте два экземпляра бота с одним токеном. Сначала остановите сервер. SQLite v1…v6 автоматически мигрирует в v7 без удаления правил, позиций, операций, команд и событий. Откат старого кода на v7 не поддерживается; резервная копия должна быть сделана **до** миграции.

## Локальное подключение токена

Создайте обычного бота через официальный **@BotFather** (`/newbot`), затем из `prototypes/rule-lifecycle` выполните **npm run setup**. При отсутствии токена команда запросит его скрытым вводом в терминале, проверит getMe и сохранит `.env` с правами 600. Существующие настройки и привязка того же бота не сбрасываются. Затем **npm run doctor**, **npm start**. Повторный запуск не интерактивен. Для перевыпуска токена/смены самого бота есть разные локальные действия; полный порядок и команды копии/восстановления — [LOCAL_USE.md](../LOCAL_USE.md).

Не отправляйте токен в чат, не вводите его в панель и не передавайте аргументом команды. Токен не попадает в SQLite, ответы браузеру и журналы. `.env` исключён из Git; не включайте отладочную трассировку HTTP, способную записать секретный URL Bot API. При утечке перевыпустите токен через BotFather.

Откройте локальную панель на том же Windows-компьютере. Внизу находится **Telegram · виртуальный режим**. Нажмите **Получить код привязки**, затем в **личном чате именно своего бота** отправьте показанную команду `/start <код>`. Код одноразовый, действует 5 минут, в базе хранится только SHA-256. Новый код заменяет предыдущий. Не передавайте код другим. Случайный `/start` без кода не даёт доступа. Подтверждённая привязка включает и Telegram user ID, и chat ID; группы, другие пользователи и другие чаты не могут читать состояние или выполнять команды.

Кнопка **Отключить привязку** в локальной панели отзывает доступ, отменяет ещё не отправленную очередь и делает старые кнопки недействительными даже после новой привязки. Уже начатую сетевую отправку отозвать невозможно; она может завершиться после отключения. Для нового владельца требуется новый код; старая история уведомлений не рассылается.

Без токена Telegram выключен; панель, SQLite и рыночные позиции продолжают работать. В панели видны подключение, привязка, очередь и число окончательно недоставленных сообщений. `401/403` — проверьте токен/права, `409` — остановите другой экземпляр getUpdates с тем же токеном, `429` — сервис сам ждёт Retry-After. При старом webhook polling не работает: удалите webhook штатным способом Bot API до запуска; приложение само не меняет чужую конфигурацию бота. При сетевой ошибке опрос бота возобновляется с задержкой; рыночный цикл не ждёт Telegram.

## Полный сценарий с телефона

После первоначальной локальной привязки отправьте `/start`. Основные кнопки: **Новое виртуальное правило**, **Текущее состояние**, **История**, **Помощь**. Команды прежние; дополнительно доступны `/new`, `/history`, `/cancel`.

**Новое виртуальное правило** ведёт по шагам: mint → загрузка поддерживаемого пула → карточка источника → цена входного условия USD/токен → виртуальная сумма USD → срок ожидания входа в минутах → TP → SL → итоговая карточка. Значения пользователь задаёт сам, рекомендуемых настроек нет. Название токена — метаданные индекса; ориентируйтесь на mint и пул. Диапазоны совпадают с панелью; десятичная запятая нормализуется без округления. Неподходящая точность отклоняется с пояснением и сохранением остальных полей.

На каждом шаге есть **Назад** и **Отменить настройку**; на первом шаге Назад возвращает меню. Отмена касается только диалога, не отзывает правило и не закрывает позицию. Черновик сохраняется на 30 минут с момента начала (без продления каждым сообщением), переживает перезапуск. Меню и уведомления не меняют шаг. **Продолжить настройку** возвращает к нему. После истечения срока требуется новый черновик. Отключение привязки аннулирует черновик и прежние кнопки.

Итоговая карточка содержит mint, пул, источник и доступность, все выбранные величины и ограничения виртуальной модели. **Подтвердить создание** относится к конкретной версии карточки; после возврата/редактирования/обновления источника старое подтверждение не действует. Созданное правило остаётся выключенным; затем нажмите отдельную кнопку **Включить правило**. Повторы и аварийное восстановление используют один устойчивый ID создания. Перед созданием сервис заново проверяет пригодность снимка, отсутствие конфликтов и закрепление пула. При конфликте с панелью значения сохраняются. После перезапуска рыночный снимок не считается актуальным автоматически: при необходимости нажмите **Обновить источник** в итоговой карточке.

Опросы используют один источник и общий cooldown. Загрузка может потребовать ожидания; повтор выбора не означает новый сигнал. Даже после успешного создания включённое правило ждёт нового пригодного наблюдения. Начатый до включения запрос не используется для входа после команды. Telegram и HTTP ждут сеть вне очереди бизнес-команд.

**Отозвать правило** доступно в текущем состоянии и деталях истории для созданного, активного или приостановленного входного правила **до передачи операции**. Бот показывает конкретные ruleId и актив, предупреждает об окончательности и предлагает **Подтвердить окончательный отзыв** или **Не отзывать правило**. Подтверждение действует 5 минут и сохраняется после перезапуска. Для временной остановки используйте паузу. Отзыв окончательный: это правило нельзя включить снова; история остаётся, а меню предлагает новое виртуальное правило и другой mint. Отмена этого подтверждения не является отменой черновика настройки; сам отзыв тоже не очищает черновик.

В момент подтверждения заново проверяются владелец, поколение привязки, конкретное правило и допустимое состояние. После входа отзыв запрещён: бот показывает существующую позицию и отдельную кнопку запроса закрытия. Unknown не разрешает отзыв до передачи или повтор операции. Отменённые/устаревшие подтверждения, другой владелец, повторные updates и прежние сообщения не управляют новым правилом. Отзыв вызывает тот же сервис `revoke`, что и панель; историю и позиции не удаляет.

**История** показывает до четырёх правил на странице и кнопки перехода; **Подробнее** открывает конкретный объект с основанием/ценой/временем входа и выхода, причиной и зафиксированным результатом. Для незакрытой позиции явно отделяется текущая оценка от последней сохранённой при недоступных данных. Меню и детали оставляют прежние паузу/возобновление/запрос закрытия с проверкой ID и состояния.

## Команды, уведомления и ограничения

- `/help`, `/start` у привязанного владельца — краткая инструкция, `/status` — актуальное правило, последняя позиция и её расчётные значения.
- Кнопки приостанавливают/включают только конкретное ещё ожидающее входное правило. Кнопка прежнего правила не влияет на новое. Использованные кнопки изменения одноразовые; для следующего действия запрашивайте `/status`.
- Запрос закрытия относится к конкретной открытой позиции: сейчас сохраняется только намерение. Расчёт производится по **следующему новому пригодному снимку**, не по цене из сообщения и не по старому кэшу. `unknown` независимо запрещает повтор соответствующей попытки.
- Уведомления: виртуальный вход, сохранённый ручной запрос, выход TP/SL/по запросу, unknown, потеря и восстановление пригодных рыночных данных. Сообщения содержат источник, актив, основание и расчётные величины; каждый снимок и каждый повтор ошибки не рассылаются. Это локальные наблюдения DEX Screener/PumpSwap, не подтверждённое время/полнота блокчейн-потока.

Привязка, поколение полномочий, кнопки, pending update, offset, распознанные события и outbox сохраняются в существующем SQLite-снимке. Перед командой сохраняется update; бизнес-операция использует стабильный ключ идемпотентности. Offset getUpdates продвигается только после сохранения обработки и ответа в очередь. Если процесс прервётся между бизнес-командой и записью offset, update восстанавливается без повторного торгового действия. События позиций/unknown сопоставляются с сохранённой историей и восстанавливают уведомления после аварии; смена доступности рынка сохраняется вместе с записью уведомления. При подключении фиксируется начальная граница истории.

Перед отправкой сохраняется номер попытки; максимум **5 попыток** с backoff, ошибки `400/401/403` окончательны для сообщения, `429` учитывает Retry-After. Очередь переживает перезапуск. Доставка **не ровно один раз**: если Telegram принял сообщение, но ответ потерялся, после рестарта возможен повтор уведомления. Уведомление никогда не исполняет торговую команду. Окончательно недоставленные сообщения не пересылаются бесконечно; актуальное сохранённое состояние доступно в панели и через `/status`. История и очередь сейчас не очищаются автоматически; это локальный прототип одного владельца, не массовый сервис.

Сетевые getUpdates/sendMessage/answerCallbackQuery выполняются вне общей очереди команд. Команды бота, панели и обработка рыночных снимков используют прежнюю сериализацию и бизнес-логику. Telegram не даёт доступ к HTTP-панели: она остаётся доверенным локальным интерфейсом без аккаунтов. Кошельки, подписи, реальные сделки и публикация приложения не добавлены.

## Документация Bot API

26.10.2026 прочитана официальная [Bot API](https://core.telegram.org/bots/api): getUpdates (offset на единицу выше сохранённого update_id; webhook несовместим), InlineKeyboardMarkup и InlineKeyboardButton (callback_data 1–64 bytes), sendMessage (1–4096 characters), answerCallbackQuery. Применяются существующие JSON-методы без parse_mode, callback_data — 24 ASCII-символа со ссылкой на сохранённую команду, исходящие сообщения ограничены 4000 символами. Меню работает через inline-кнопки, изменение публичного меню команд бота не требуется. Прямая страница сначала была недоступна по политике среды; после разрешения core.telegram.org она получена по HTTPS. Дополнительно сверены обработчики в официальном tdlib/telegram-bot-api. Это проверка контрактов, не живого бота.
