# Реальные рыночные снимки, виртуальные операции

Источник: публичный **DEX Screener API**, [официальная справка](https://docs.dexscreener.com/api/reference), проверена 21 октября 2026. Используется только `GET https://api.dexscreener.com/token-pairs/v1/solana/{mint}`. Доступ проверен без ключа и оплаты. Вызовы делает Node-сервер, браузер обращается только к локальной панели. `npm start` использует штатный `--use-env-proxy` Node.js 24.19.0: в Cloud прямой исходящий fetch не работал, запрос через настроенный средой proxy успешно получен; проверка TLS не отключается.

## Граница поддержки

Только пары, которые индекс пометил `chainId=solana`, `dexId=pumpswap`, где введённый **точный mint** — `baseToken.address`, а `quoteToken.address` — WSOL `So11111111111111111111111111111111111111112`. Mint проверяется как Base58 с декодированием в 32 байта; названия/тикеры для идентификации не используются. Совпадение имени не доказывает подлинность токена.

При первоначальном выборе берётся пул с наибольшей **заявленной агрегатором** `liquidity.usd`, при равенстве — по адресу. Пул и пара показаны до создания правила. Правило сохраняет режим `market-paper`, провайдера, сеть, dex, mint, адрес пула, quote mint и поле цены; после выбора пул автоматически не заменяется. Если он исчез из ответа, показывается отсутствие данных. Другая площадка, обратная пара, WSOL как base, отсутствующая USD-цена или слишком точное значение не подставляются.

Это **не поддержка bonding curve Pump.fun**, не подтверждение происхождения токена, не прямое чтение программы PumpSwap и не onchain-проверка пула. Площадка и метаданные показаны по данным индекса DEX Screener. Если API пока не индексирует нужный пул или токен ещё на bonding curve, панель объясняет отсутствие поддержки.

## Цена, время и опрос

Для условия используется **`priceUsd`: USD за один целый токен**. Пара самого пула — токен/WSOL, а priceUsd — USD-оценка агрегатора; эти две валюты явно различаются в UI. `priceNative` не используется. Цена и порог переводятся без float-округления в целые доли USD с масштабом **10⁹**. Положительные значения до 9 значимых знаков после запятой; дополнительные нули допустимы. Более точные/малые значения отвергаются с объяснением. Виртуальная сумма вводится до двух знаков после запятой и сохраняется в тех же долях USD; количества токенов из неё не рассчитываются.

Это периодические HTTP-снимки, **не поток сделок**. Локальная квота общая для выбора и опроса: не чаще одного запроса за 10 секунд, без параллельных запросов. Кнопка выбора во время cooldown планирует новый mint на следующий допустимый опрос; она не обходит ограничение частоты. При ошибках — задержка 20/40/80/120 секунд; для HTTP 429 дополнительно учитывается Retry-After с минимумом в минуту, указанная сервером более долгая задержка не сокращается. Лимит относится к одному экземпляру панели, не ко всем программам, использующим тот же IP. Платные тарифы не подключаются.

API не предоставляет ID сделки, курсор, полноту истории, slot/finality или timestamp конкретной цены. `pairCreatedAt` — время создания пары, оно **не** используется как время цены. Событие `market-price-snapshot` содержит:

- `mint`, `assetId=SOLANA:{mint}`, неизменный источник/пул/пару и точные единицы;
- исходную строку `rawPriceUsd` и целые `priceUnits`;
- `observedAtMs` — локальное начало HTTP-запроса; `receivedAtMs` — локальное время получения;
- `providerUpdatedAtMs=null`, `idKind=local-observation`, случайный локальный ID наблюдения.

ID нужен только для локальной идемпотентности записи. Он **не является ID провайдера**. Курсор/позиция блокчейна не создаются. Проверка 45 секунд относится к возрасту локального наблюдения, а не доказывает свежесть цены у агрегатора; его кэш/задержка остаются неизвестны. UI показывает получение, отсутствие данных, загрузку/ожидание квоты, ошибку, локальное устаревание и восстановление опроса. При сетевом сбое старая цена может оставаться видна с предупреждением, но **не передаётся заново в правило**.

После восстановления используется только новый успешный снимок. Между наблюдениями и во время остановки сервера могли быть пропущены движения, они не восстанавливаются. В этом режиме нет обещания непрерывности и нет разрешения `decision_required` через снимки. Существующие решения по синтетическому журналу и отключённый accept_gap не расширяются.

## Виртуальное правило и сохранение

Создание не включает правило и не исполняет уже показанный снимок. После включения ядро оценивает только новые подходящие наблюдения закреплённого источника. DEMO-пульт запрещён для рыночного правила; выбор другого mint при незавершённом правиле запрещён. Для нового режима/актива требуется завершить или отозвать текущее правило и создать отдельное.

Ядро сохраняет наблюдение и намерение в одном SQLite-снимке. Далее используется прежняя граница prepared/submitted/результат. Виртуальный исполнитель возвращает только `kind=virtual-condition`, без квитанции покупки, выдуманного количества токенов, комиссий, доходности или цены исполнения. «Виртуальное условие выполнено» означает только выполнение сравнения на полученной цене. Это не моделирование ликвидности, slippage/min-out или реального обмена.

После перезапуска активное правило ждёт нового HTTP-снимка; сохранённые цены не переигрываются. Сохранённое prepared-намерение отменяется, правило ставится на паузу и требует явного включения; уже возможная передача без результата восстанавливается как unknown, блокировка остаётся. Завершённые/отозванные/истёкшие правила не оживают. Устаревшие или пришедшие в обратном порядке локальные наблюдения не дают новый сигнал. Сохранённая конфигурация расширена дополнительными типами в прежнем v3-снимке; существующие базы панели читаются без сброса.

## Проверка через интерфейс

```bash
cd prototypes/rule-lifecycle
npm start
```

Node.js **24.19.0**, без npm install. На компьютере, где запущен сервер, откройте **http://127.0.0.1:4173**. Это не внешний адрес Cloud. [Windows через WSL](../../../HANDOFF.md#windows).

1. Если есть открытое правило, завершите/отзовите его; нажмите «Новое правило»/«Новое DEMO-правило».
2. В форме выберите **«Рыночные снимки · виртуально»**. Введите свой mint и нажмите **«Загрузить токен»**.
3. Проверьте mint, пул, пару токен/WSOL и USD-цену в карточке. Если данных нет, причина показана там же; другого источника автоматически не будет.
4. Укажите свой **тестовый** порог в USD/токен, виртуальную сумму и срок. Создайте и включите правило.
5. Дождитесь новых снимков. При выполнении условия появится **«Виртуальное условие выполнено»**. Обновление страницы и перезапуск сервера сохраняют результат.

Для воспроизведения живой проверки использован публичный mint `HnXDnwTa68tRhLRZdJkVRLAeYrUkCYgFgDavtwD1pump`, пул `eUsB7o5HXb4xj3RD4eZjumRV6T65PQELbhd8mNFRjk6`. Это адрес из проверочного ответа, **не рекомендация** и не доказательство подлинности токена. Доступность пула может измениться. Искусственный проверочный порог 1.00 USD использовался только для получения виртуального срабатывания; движение реальной цены не имитировалось.

## Живые и воспроизводимые проверки

`npm test`: прежние 112 проверок плюс `market.test.mjs`. Рыночные проверки используют **сохранённый публичный ответ** в `fixtures/dexscreener-pumpswap.json`, а не сеть; производные варианты явно создаются внутри тестов. Убраны изображения/социальные ссылки, нет данных держателей или пользовательских идентификаторов. В provenance указаны URL, время сохранения и хеши.

```bash
python3 web/market-browser-check.py          # OFFLINE: сохранённый ответ, явно изменяемые сценарии
python3 web/market-browser-check.py --live   # LIVE: публичный API, только виртуальные операции
python3 web/browser-check.py                # прежний синтетический DEMO
```

Дополнительные браузерные команды требуют отдельно доступных Python Playwright и Chromium. Offline harness находится только в test-support, принимает управление по stdin и не подключён к npm start/API панели. Он не доказывает доступность живого источника. Итоговые отчёты и фактические границы — [VALIDATION.md](../VALIDATION.md).


## Повторная загрузка и следующее правило

С 23 октября 2026 пригодность снимка (`snapshotUsable`) отделена от расписания опроса (`pollStatus`). Повторный выбор того же mint/пула до следующего запроса не продлевает возраст снимка, не переотправляет его в правило и не делает пригодный снимок недоступным для формы. Ошибки/устаревание по-прежнему запрещают создание, другой mint очищает прежний снимок. В UI показаны обе величины; после фонового восстановления данных прежняя ошибка источника в поле mint снимается для совпадающего введённого адреса.

После завершения, истечения срока или окончательного отзыва нажмите «Новое правило», явно выберите режим/тот же mint и задайте параметры. Это новое правило с новым ID, старое остаётся в журнале. Пауза не даёт создать следующее правило, пока текущее не закрыто. Unknown не снимается повторной загрузкой.
