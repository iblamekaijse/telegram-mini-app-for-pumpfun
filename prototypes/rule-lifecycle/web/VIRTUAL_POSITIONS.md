# Виртуальная позиция на рыночных снимках

Локальная DEMO-панель, Node.js **24.19.0**, без новых зависимостей. Запуск из корня:

```bash
cd prototypes/rule-lifecycle
npm start
```

Откройте **http://localhost:4173** в браузере того компьютера, где запущен сервер (для Windows — сервер в WSL). Это не внешний адрес Cloud. Кошельков, подписей, реальных сделок и настоящей авторизации нет.

## Через панель

1. При необходимости завершите/окончательно отзовите прежнее правило и нажмите «Новое правило». Старые правила не становятся позициями автоматически.
2. Выберите «Рыночные снимки · виртуально» и **«Виртуальная позиция · вход и выход»**. Введите mint и загрузите токен. Проверьте выбранный пул PumpSwap токен/WSOL и USD за токен; bonding curve Pump.fun не поддерживается.
3. Введите своё условие «цена не выше», виртуальную сумму USD, срок ожидания входа, TP и SL в процентах. Создайте и включите правило. Значения не предзаполнены торговыми рекомендациями. Ценовое поле поддерживает до 9 десятичных знаков без округления; сумма — до 2. TP: 0.01…10000%, SL: 0.01…99.99%; проценты — до 2 знаков. Сумма/цена дополнительно ограничены безопасным диапазоном целых единиц существующего контракта.
4. Следующий новый пригодный снимок с ценой ≤ условию завершит входное правило и откроет позицию. В карточке появятся сумма, условное количество, модельная цена входа, оценка, результат и уровни выхода. Можно перезагрузить страницу и перезапустить сервер с той же `.local-web`.
5. Позиция закроется на новом пригодном снимке по TP/SL. Либо нажмите **«Закрыть виртуальную позицию»**: запрос сохранится, расчёт подождёт следующего нового пригодного снимка. Пока его нет, состояние — «Ожидаем закрытия». Кнопка не использует старую цену.
6. После закрытия результат и основания видны в карточке, журнале и раскрываемой истории позиций. Можно явно создать новое правило. Пока позиция открыта или ждёт закрытия, создание другого правила и переключение источника/пула запрещены сервером; в UI соответствующие действия недоступны.

Для быстрого **тестового** входа можно самостоятельно поставить условие не ниже текущего priceUsd. Это не рекомендация покупки: вход всё равно ждёт нового снимка. Для воспроизводимых чисел и всех видов выхода используйте offline-проверку ниже — реального движения рынка ждать не нужно.

## Модель и переходы

**Идеализированный расчёт по цене агрегатора без учёта исполнения, комиссий и проскальзывания. Условное количество не является onchain-балансом.**

- Цена входа = priceUsd нового пригодного снимка, выполнившего условие, а не порог формы.
- Количество = сумма / цена входа; оценка = количество × наблюдаемая цена.
- Результат USD = оценка − сумма; результат % = результат / сумма × 100.
- TP = цена входа × (1 + TP% / 100); SL = цена входа × (1 − SL% / 100).
- Входные цены/суммы в прежних целых USD-единицах 10⁻⁹; далее сокращённые рациональные дроби BigInt `{n,d}` с десятичными строками в JSON. Деление не округляется. Только отображение округляется: количество до 12, остальные показатели до 9 знаков, половина от нуля. Все точные основания сохранены.

**Явно тестовые примеры:** сумма 1000 USD, вход 100 USD → 10 условных токенов; выход 110 → +100 USD/+10%; выход 90 → −100 USD/−10%. При TP 10% и скачке до 125 выход рассчитывается по 125, результат +250 USD/+25%, а не по уровню 110. Эти числа не относятся к живому токену.

| Объект / состояние | Событие | Результат |
| --- | --- | --- |
| Входное правило draft/paused | Включение, прежние проверки | active; ждёт нового снимка |
| Входное правило active | Условие выполнено, подтверждён виртуальный результат | finished + позиция open, одна транзакция SQLite |
| Ещё не выполненный вход | Истечение / пауза / отзыв | Прежняя семантика; позиции нет |
| Позиция open | Последующий новый пригодный снимок | Оценка; закрытие по TP/SL при выполнении |
| Позиция open | Команда закрытия | close_requested, команда и запрос атомарны |
| Позиция close_requested | Новый пригодный снимок, начатый строго после запроса | closed, причина user_request |
| Позиция open/close_requested | Нет данных, ошибка, устаревание, перезапуск | Состояние сохраняется, актуальной оценки нет до нового пригодного снимка |
| Позиция closed | Reload, повторы, перезапуск | Не открывается и не закрывается заново; результат сохранён |

Входное правило и позиция отдельны. Срок ограничивает ожидание входа; после входа позиция не истекает вместе с ним. TP/SL проверяются лишь при строго возрастающем локальном времени начала запроса, на том же источнике/mint/пуле и в тех же USD-единицах. Снимок входа не используется для выхода. Идентификаторы наблюдений локальные, не ID сделок или курсоры DEX Screener. Повтор ID с изменённым содержимым отклоняется; точный повтор не создаёт новую оценку/выход. Запоздавший/будущий/устаревший снимок не закрывает позицию.

Ручное закрытие имеет приоритет на следующем пригодном снимке, начатом после запроса. Если снимок начат раньше запроса, он не исполняет ручное закрытие; обычные TP/SL всё ещё применяются к пригодному последующему снимку. Сериализация запросов панели исключает параллельную подмену этого решения. Повтор команды с тем же ключом возвращает прежний результат; даже другой ключ не переносит уже сохранённую границу запроса.

## Хранение и границы гарантий

SQLite остаётся единственным хранилищем, без сервера БД. Версия снимка **v4** добавляет `positions`; при открытии v3 добавляется пустая коллекция, прежние правила/операции/команды/бюджеты/журналы не меняются. Старые v1/v2 проходят прежние миграции, затем v4. Новые позиции создаются только для явно выбранного сценария.

Подтверждённый результат входа и создание позиции сохраняются одной транзакцией. Выход, основание, точные результаты и распознавание повтора снимка также сохраняются вместе. Обрыв до сохранения результата входа восстанавливает прежнюю неопределённость `unknown`, без позиции и без автоматического повтора. Это не обещание «ровно одного» внешнего исполнения: внешнего исполнения здесь вообще нет. Выход — чистый локальный расчёт, без отправки имитатору внешней продажи.

После перезапуска нет текущей цены до нового успешного опроса; сохранённые цены остаются основаниями истории. Открытая позиция ждёт наблюдения, начатого не раньше нового процесса и позже последнего принятого снимка. История пропущенного интервала не восстанавливается. Свежесть относится к локальному запросу (≤45 с), не доказывает свежесть priceUsd у провайдера. Опрос ≥10 с и существующие backoff/Retry-After не изменены. Между снимками возможны незамеченные движения, достижимость цены и прибыльность не подтверждены.

Прежняя эксклюзивная блокировка SQLite запрещает второй экземпляр с тем же хранилищем. Недоступная/повреждённая база не становится пустой историей. `unknown` по входной операции независимо запрещает повтор этой попытки; решений, объявляющих её неисполненной, нет. `accept_gap` остаётся отключённым. Доверенный localhost DEMO-контекст не подтверждает полномочия реального владельца.

Обновляйте существующую `.local-web`, не удаляя её. Перед первым запуском v4 остановите сервер и сохраните копию каталога вне репозитория. Возврат старого кода на уже обновлённую v4 не поддерживается; старый код откажется читать новую версию. Инструкция обновления — [HANDOFF](../../../HANDOFF.md).

## Воспроизведение проверок

```bash
npm test
# Только при отдельно установленных Python Playwright и Chromium:
python3 web/positions-browser-check.py
```

Тесты используют временные SQLite. Browser harness читает сохранённую форму ответа DEX Screener и явно тестовые цены 100/105/107/110/90. Меняется только тестовый транспорт вне `npm start`; пользовательские цены не добавлены в рыночный API панели. Проверяются реальные HTTP/ядро/SQLite, двойные нажатия, reload, SIGKILL и новый процесс с открытой позицией, отсутствие оценки до данных, ручной выход +70 USD/+7%, TP +100/+10%, SL −100/−10%, история и мобильная ширина. Источник synthetic DEMO остаётся отдельным, его прежний сценарий не менялся.

Отдельный [LIVE-отчёт](../results/positions-live-source.json) — один запрос чтения DEX Screener, без создания правил/позиций. Он проверяет доступность формата ответа, а не прохождение тестовых порогов в живом рынке.
