Бот подготовлен к регулярному локальному использованию: существующий checkout обновляется без переустановки, затем выполняются согласованная копия реальной SQLite/.env, единая настройка, диагностика и обычный неинтерактивный запуск. После первоначальной привязки пользователь проходит полный виртуальный цикл с телефона: создание/подтверждение/включение или окончательный отзыв до входа, уведомления, закрытие, история.

Этот PR включает рыночные снимки DEX Screener/PumpSwap, виртуальные позиции, Telegram-интерфейс и их локальную эксплуатацию. Продолжена существующая ветка codex/virtual-position-lifecycle, база по-прежнему codex/pumpswap-price-snapshots (PR №2), без новой цепочки PR и без слияния в main. Кошельков, реальных сделок, Mini App и публичного сервера нет.

Добавлены npm run setup (скрытый ввод/getMe, сохранение настроек и .env 600), npm run doctor (чёткие исправно/не настроено/не проверено/ошибка), backup и restore. Doctor читает живой read-only endpoint либо SQLite read-only без миграции; не потребляет updates, не отправляет сообщений, не запускает рыночный запрос и не снимает webhook. Backup требует остановки и подтверждает её эксклюзивной SQLite-блокировкой, проверяет полученную копию; конфигурация остаётся только локально с ограниченными правами. Restore по умолчанию создаёт новый каталог и направляет туда .env; перезапись требует точного пути и сохраняет предшествующее состояние. Повреждённые/несовместимые данные не становятся пустой историей.

SQLite v7 хранит проверенный ID бота, сохраняя историю и прежние Telegram-записи. getMe/getWebhookInfo выполняются до polling, очереди, pending-команд и dialog source-jobs. Перевыпуск токена того же ID сохраняет доступ; смена бота требует отдельного явного локального действия и сбрасывает только Telegram-состояние. v6 не сохраняла ID: продолжение прежнего доступа требует явного принятия прежнего бота, автоматическая идентификация прошлого не заявляется. Сохраняются диалог на 30 минут, версии/ID подтверждений, отдельное включение, подтверждённый окончательный отзыв до передачи, неизвестный исход и закрепление пула. Сеть выполняется вне очереди бизнес-команд, действует прежний cooldown; доставка уведомлений не обещана exactly-once.

Проверено новым итоговым прогоном на Node.js 24.19.0: 212 tests passed, 0 failed/skipped/cancelled (195 прежних + 17 операционных), все шесть существующих browser-сценариев. Сквозной setup → живой локальный HTTP/SQLite/long-poll с тестовыми транспортами → виртуальный цикл → остановка/копия → новый каталог/doctor → запуск с теми же историей, доступом и единственной операцией. Проверены старый и другой bot ID, webhook, no-op doctor, права/повреждение/несовместимость/перезапись/блокировка, actual npm start/doctor/backup/restore и реальный Linux pseudo-terminal без эха секрета. Отчёты: prototypes/rule-lifecycle/VALIDATION.md и results/local-*.
