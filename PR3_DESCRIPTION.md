Панель теперь позволяет привязать одного владельца к обычному Telegram-боту и управлять существующим виртуальным торговым циклом с телефона. После нового рыночного снимка бот сообщает о виртуальном входе; кнопка закрытия сохраняет запрос, следующий пригодный снимок рассчитывает выход и уведомление. Реальных сделок, кошельков, Mini App и публичного сервера нет.

Включены рыночные снимки DEX Screener/PumpSwap и виртуальные позиции из исходного PR №3: точная рациональная арифметика, TP/SL и ручной выход. База остаётся codex/pumpswap-price-snapshots (PR №2); эта ветка продолжает прежний PR №3, без новой цепочки и без слияния в main.

Telegram: необязательный локальный .env, long polling вне очереди команд, одноразовый код из панели с TTL, user ID + private chat ID, отзыв полномочий и поколение кнопок. SQLite v5 сохраняет прежнюю историю и добавляет pending update/offset, одноразовые кнопки, границу событий и outbox. Повторы updates не повторяют команды; неизвестный исход остаётся заблокирован. До 5 попыток доставки, Retry-After; возможен повтор сообщения при потерянном ответе, доставка exactly-once не заявляется. Первичная привязка не рассылает прошлую историю. Без Telegram панель и рынок работают.

Проверено в новом прогоне на Node.js 24.19.0: 172 tests passed, 0 failed/skipped; новый сквозной Chromium-сценарий панели и long-poll бота с тестовыми транспортами; четыре прежних browser-сценария; четыре CLI demo; фактический npm start; миграции v1…v4 → v5, SQLite restart/SIGKILL, отзыв/чужой владелец/старые кнопки, pending recovery, очередь/Retry-After и ошибки API. Отчёты: prototypes/rule-lifecycle/VALIDATION.md и results/telegram-*.

Не проверены настоящий Telegram без токена, текущий live DEX Screener и WSL пользователя. Не выдаём тестовый транспорт за живую интеграцию. Обновление существующей WSL с резервной копией: HANDOFF.md#update; локальный токен и одна итоговая приёмка: prototypes/rule-lifecycle/web/TELEGRAM.md.
