# Локальный виртуальный выпуск v0.1.0-paper.1

Актуальный код — **main**, фиксированная версия — **v0.1.0-paper.1**. Node.js **24.19.0**, SQLite **v7**. PR №2 и №3 включены в этот выпуск с сохранением истории. Зависимые ветки больше не являются источником обычной установки. [Состав и проверки выпуска](RELEASE.md).

**Уже установлен d99f6f5…:** функциональных изменений приложения в выпуске нет. Можно продолжать работать без обновления, повторной настройки и дополнительной приёмки. Переход на main можно выполнить при следующем плановом обновлении.

<a id="windows"></a>
## Новая установка

Для Windows используется существующая Ubuntu/WSL 2 и Linux Node.js 24.19.0. Пользователь уже подтвердил этот Node и запуск в своей WSL. Новому пользователю сначала нужны Git и Node.js 24.19.0; native Windows и хранение на сетевом диске не проверены. Сохраняйте проект в домашнем каталоге Ubuntu, а не в /mnt/c. Команды — в Ubuntu, без переустановки уже существующего checkout:

```bash
git clone --branch main https://github.com/iblamekaijse/telegram-mini-app-for-pumpfun.git
cd telegram-mini-app-for-pumpfun/prototypes/rule-lifecycle
npm run setup
npm run doctor
npm start
```

Setup нужен для первого подключения Telegram. Он читает существующие настройки, при необходимости запрашивает токен скрытым вводом в терминале, проверяет getMe и сохраняет .env с правами 600. Токен не передавайте в переписку или аргумент команды. Панель без Telegram можно запустить обычным npm start без вопросов. Для сверки фиксированной версии: `git rev-parse 'v0.1.0-paper.1^{commit}'` и `git show v0.1.0-paper.1:prototypes/rule-lifecycle/package.json`.

<a id="update"></a>
## Единственный путь обновления существующего checkout

1. Остановите сервер **Ctrl+C**, дождитесь приглашения оболочки. Если версия d99f6f5… уже работает, выполнять обновление сейчас не требуется. Иначе из любого каталога существующего checkout выполните блок ниже. Он сохраняет ссылку на старый commit, переключает только исходники на актуальную main, затем проверенной командой копирует фактические SQLite и .env **до настройки/миграции/запуска**. Git не удаляет игнорируемые файлы. При собственных правках процедура останавливается; сохраните их, не используйте reset/clean.

```bash
(
  set -e
  cd "$(git rev-parse --show-toplevel)"
  if [ -n "$(git status --porcelain)" ]; then
    git status --short
    echo "Сначала сохраните собственные изменения; обновление остановлено."
    exit 1
  fi
  PANEL_UPDATE_STAMP=$(date +%Y%m%d-%H%M%S)
  git branch "backup/before-main-$PANEL_UPDATE_STAMP" HEAD
  git fetch origin refs/heads/main:refs/remotes/origin/main --tags
  git switch --create "local/main-$PANEL_UPDATE_STAMP" --track origin/main
  git rev-parse HEAD
  cd prototypes/rule-lifecycle
  npm run backup -- --to "$HOME/pumpfun-backups/before-$PANEL_UPDATE_STAMP"
)
```

Если раньше использовался DEMO_ENV_FILE, сохраните его в оболочке. Все команды определяют реальную базу по тому же файлу; относительный DEMO_DATA_DIR разрешается из каталога приложения. Backup проверяет эксклюзивную блокировку и отказывает для работающего экземпляра. Не заменяйте его простым cp открытой базы. Если базы ещё не было, копия настроек помечается без истории; пустая история вместо существовавшей не создаётся.

2. **Настройка только при необходимости.** Из каталога `prototypes/rule-lifecycle` выполните `npm run setup`, если токен ещё не задан, перевыпущен, меняется бот или старая база не содержит подтверждённого ID. При уже успешных setup/getMe/ID/webhook и сохранённых настройках пропустите этот шаг. Из v6 прежний ID автоматически установить нельзя — setup попросит явное принятие прежнего бота; историю/привязку того же бота он сохраняет. Явная смена бота — отдельное действие, описанное в LOCAL_USE.md. Миграции v1…v6 → v7 сохраняют историю; старый код v7 не читает.

3. Диагностика и запуск из того же каталога:

```bash
npm run doctor && npm start
```

Doctor не мигрирует базу, не получает updates, не отправляет сообщений и не делает рыночный запрос. Для остановленного сервера «панель/рынок не проверено» ожидаемо. При ошибке выполните указанное действие до запуска; не удаляйте .env или базу. Setup и повторную привязку не нужно повторять для уже подтверждённого того же бота.

## Работа и границы

На компьютере запуска панель доступна по `http://127.0.0.1:4173` (в Windows с WSL также `http://localhost:4173`). Это локальные адреса, не Cloud-preview и не доступ к панели с телефона. Телефон использует обычный личный чат бота; для первой привязки нужен одноразовый код из локальной панели. Сервер не публикуется в интернет. Компьютер, WSL и процесс должны оставаться включёнными; остановка — Ctrl+C. После перезапуска сохраняются правила/позиции/история/привязка, а актуальная оценка ждёт нового пригодного снимка.

Источник рынка — DEX Screener, индексируемые PumpSwap токен/WSOL, priceUsd. Только виртуальные расчёты без исполнения/комиссий/проскальзывания. Полнота потока, возраст цены агрегатора и достижимость цены не гарантируются; неизвестный исход не разрешает повтор. Нет реальных сделок, кошельков, Mini App, публичного сервера и новых источников. Поиск подписи не возобновлён.

[LOCAL_USE.md](prototypes/rule-lifecycle/LOCAL_USE.md) содержит команды регулярной эксплуатации, типовые ошибки и безопасное восстановление в новый каталог. Для следующего этапа настоящей интеграции подготовлен отдельный [единый прогон LIVE_CHECK.md](prototypes/rule-lifecycle/LIVE_CHECK.md) из новой ветки с PR в main. Он не включён в неизменяемый тег v0.1.0-paper.1; повторять старую ручную приёмку и успешный setup не требуется. Исторические этапы и отчёты сохранены в [брифе](PROJECT_BRIEF.md) и [VALIDATION.md](prototypes/rule-lifecycle/VALIDATION.md).
